# `vci_read` / `vci_write` (PR 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two standalone-only tools over the TIA Portal Version Control Interface. `vci_read` lists workspaces,
mappings with optional status, and supported formats. `vci_write` creates and deletes workspaces, exports scopes
into a mirrored layout, synchronizes in either direction, and deletes mappings. Results report counts. A Portal
crash or a worker timeout names the last attempted leaf.

**Architecture:** Pure decision logic lives in `TiaMcpServer.Contracts/Vci`: scope vocabulary, formats, status
filter, mirrored paths, path policy and breadcrumb. The worker (`Openness/Vci/`) resolves a scope, expands it to
leaves and makes only Openness calls. `vci_read` follows the `plc_read` batch model. `vci_write` is an
`IWriteDomain` on `Safety/Pipeline`, shaped like `hmi_write`. It plans through one Observe worker method,
`vci_plan`, that never reads status.

**Tech Stack:** C# (host net10.0, worker net48, contracts netstandard2.0), Openness V21
`Siemens.Engineering.VersionControl`, xunit, ModelContextProtocol SDK, FakeWorker.

**Spec:** [docs/superpowers/specs/2026-10-15-vci-tools-design.md](../specs/2026-10-15-vci-tools-design.md) §3–§10
(§ numbers below refer to it). Openness facts come from the [VCI spike](../acceptance/reports/2026-10-15-vci-spike.md).

## Decisions this plan adds to the spec

The code forces these choices. Each one fills a gap in the spec or corrects it. Task 14 carries them into the docs.

- **E1 Scope vocabulary.** `browse_project_tree` emits no technology-object or HMI nodes. VCI therefore gets its
  own node vocabulary. It reuses the PLC node types and adds `TechnologyObjectFolder`, `TechnologyObject`,
  `HmiSoftware` and `ScriptModule`. HMI names come from `hmi_read list_hmi_devices`.
- **E2 Software units and system blocks are out.** A scope segment `SoftwareUnit` or `SystemBlockFolder` gives
  `target_kind_unsupported`. Expansion never descends into units or system block groups. The tool description says so.
  `list_mappings` still reports their mappings, with the tree's `SoftwareUnit`/`SystemBlockFolder` segments in the
  path. A library object never reaches a Device, so its mapping gets `path:null`, the same as a deleted object.
- **E3 Mirrored layout** is always `<device>/<software>/<category>/<user groups…>/<leaf>`. A Unified HMI uses the
  category `Scripts`. The scope's root folder segment (for example the root block group) is replaced by the
  category. The UI omits the software level for a hardware PLC. Live step 1 records that difference; v1 keeps both levels.
- **E4 Format names** are passed through exactly as Openness spells them. Openness uses `SimaticML`, `SimaticSD`,
  `SCL` and `DB`, and UI workspaces also contain `UDT` and `liblink`. The host checks only that `format` is not
  blank. Each leaf matches it case-insensitively against its own `GetSupportedFileFormats`. A substitution is
  counted whenever the format used differs from `format ?? "SimaticML"`. The on-disk collision check matches the
  file stem (`<leaf>.*`), so it needs no table of extensions per format.
- **E5 Project-folder rule runs at plan time.** `Validate` has no project path. `rootPath` inside the bound
  project's folder (`ArchiveDirectoryGuard.IsWithinProjectFolder`) fails the plan with
  `WritePlan.Fail(validation_error)`. It is not a block guard, unlike the lifecycle `archive_inside_project_folder`.
- **E6 Planning** uses one worker method per item, `vci_plan`. It is classified Observe and maps to `vci_write`.
  It never calls `GetStatus()`. Guards list at most 10 offending leaves.
- **E7 Dependencies.** An item depends on the nearest earlier item in the call that names the same workspace
  (case-insensitive). The pipeline then plans it again (`ReplanAsync`) after that item has run.
- **E8 Breadcrumb transport.** `RequestId` and `BreadcrumbPath` travel in `VciWriteRequestInfo`, so
  `WorkerRequest` and the protocol version stay unchanged. The domain reads the breadcrumb after every write call
  and uses it only on `worker_timeout` or `worker_crashed`. `lastAttempted` goes into the failure message.
- **E9 Leaf failures.** When a leaf fails, the worker returns
  `Failure(worker_operation_failed, …, vciWriteOutcome)` for that item. The pipeline then stops at that item.
- **E10 No private path copy is swapped** to the shared policy. None of the swaps is mechanical: the reserved-name
  lists differ. Task 14 logs this as a follow-up.
- **E11 All six write methods** enter the worker through `WithActiveContext`, because `sync_to_project`'s
  `ExclusiveAccess` needs `session.TiaPortal` and one path is simpler than two. Reads and `vci_plan` use
  `WithEngineeringRoot`. Both cast the root to `Project`. Never use `RequireStandaloneOwner()`
  (`ActiveProjectContextSourceTests` pins it at four uses).
- **E13 Mapping keys are relative.** `MappedObject.DirectoryPath` is absolute: it includes the workspace root
  (spike `q0-inventory`). `fileKey` and every collision comparison use `VciFileKey.FromMapping`, which strips the root.
- **E14 Verification re-plans.** Export and `delete_mapping` are verified by running `vci_plan` again over the same
  scope, so unit, system-block and library mappings never skew the totals. Only the last item per workspace is
  checked; earlier items in that workspace are `superseded`. After any `portal_lost`, `worker_timeout` or
  `worker_crashed`, verification makes no reads.
- **E12 `supported_formats` takes an optional `workspaceName`.** `GetSupportedFileFormats` is a `Workspace`
  method. Without a name, the first workspace of the project is used. A project with no workspace gives
  `target_not_found`, with guidance to create one first.

## Global Constraints

- Counts move from 7/17/17 to **8/19/19**. `vci_read` is registered in every mode. `vci_write` is registered only
  when `ProjectMutation` is allowed.
- Both roots use `contractVersion:"1.0"` (`VciContractVersion.Current`), are canonical JSON, and have no nested JSON strings.
- 1–50 items per call. `operationId` values are unique and at most 256 characters. One project path per call.
- `list_mappings`: `offset` ≥ 0 (default 0); `limit` 1–200 (default 100).
- Budgets come from the effective `StructuredOperationBatchPayloadBudget.MaxItemChars` / `MaxDocumentChars` and
  never from a literal.
- Worker methods:
  - Observe: `vci_list_workspaces`, `vci_list_mappings`, `vci_supported_formats`, `vci_plan`.
  - ProjectMutation: `vci_create_workspace`, `vci_delete_workspace`, `vci_export`, `vci_sync_to_workspace`,
    `vci_sync_to_project`, `vci_delete_mapping`.
- Guard ids:
  - block: `vci_file_key_collision`, `vci_name_not_representable`, `vci_workspace_exists`, `vci_state_unverifiable`
  - info: `vci_files_remain`, `vci_import_unvalidated`
- New failure category `portal_lost`. The host invalidates the binding on it at once.
- Status comes only from `GetStatus()`, never from `Status`. `Synchronize` is never called on an `Equal` mapping.
  No container is ever passed to `ExportObject`, `Synchronize` or `GetSupportedFileFormats`.
- Catch `NonRecoverableException` **before** `EngineeringException`. The test doubles derive it from
  `EngineeringException`, so the wrong order is CS0160.
- Live Openness objects are compared with `object.Equals`. Never dispose a `TiaPortalProcess`.
- No project, device or block name and no `.ap21` path in any repo file, test, commit or report.
- Navigate C# through jCodemunch. Build with `-m:1`. Run `dotnet` commands that take `/p:` flags from PowerShell.
- Each task ends in one short, one-line conventional commit with no body and no trailers.
- README, AGENTS and `docs/` change only in Task 14. The live report is the exception.

## Review Focus

1. **Running the same export again** must skip every leaf as `alreadyMapped`. Their own files on disk are not
   collisions. Test: Task 8 `RerunExport_AlreadyMappedLeavesAreNotCollisions`.
2. **`create_workspace` then `export` in one call** must plan the export after the create, through `dependsOn`, and
   must not fail with `target_not_found`. Test: Task 11 `ExportAfterCreateInSameCall_DependsOnCreate`.
3. **A leaf named `CON`, or a name ending in a dot,** fires a block guard that names the leaf. Nothing is exported.
   Tests: Task 3 `ReservedAndTrailingDotNames_AreNotRepresentable`, Task 8 `UnrepresentableLeaf_ReportedByPlan`.
4. **`sync_to_project` where every mapping is `Equal`** opens no transaction and makes no `Synchronize` call. The
   item succeeds with every leaf counted under `skipped.equal`. Test: Task 9 `AllEqual_OpensNoTransaction`.
5. **A PLC scope containing software units or system blocks** exports only the regular leaves. A scope that names a
   unit or a system folder directly is `target_kind_unsupported`. Tests: Task 2 `UnitOrSystemFolderScope_IsKindUnsupported`,
   Task 6 `PlcSoftwareScope_SkipsUnitsAndSystemBlocks`.
