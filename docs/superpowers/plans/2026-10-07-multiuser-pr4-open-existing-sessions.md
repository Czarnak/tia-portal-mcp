## Global Constraints

- “Host and contract projects remain Siemens-free.” Siemens calls run only in the net48 worker.
- “Read-only can adopt an already-open session; it cannot open one.” Configured selectors, reads and inspection never implicitly open.
- “Selection is exact and deterministic.” Zero matches returns `target_not_found`; more than one match returns `target_ambiguous`.
- “Path is not owner continuity.” Include owner kind, exact Portal PID and live owner/generation evidence; same/ambiguous paths, owner replacement and unproved remote-session association fail closed.
- “An ALS opening input is provenance, not cold-adoption identity.” Cold adoption reports `sessionContainerPath:null`; never reconstruct it from filenames, parent directories or private session data.
- “Mode is populated only from trusted operation provenance or exact server/session resolution; otherwise it remains `unknown`.” Never infer mode from `_LS`/`_ES` filenames.
- “Adopting an already-open local session does not make it worker-owned. Ownership does not survive detach or reattachment.”
- “The worker never calls `LocalSession.Close()` as unconditional cleanup.” Generic `close_project` remains standalone-only.
- “Capabilities are descriptive, not authorization.” Unsupported local-session operations fail before mutation dispatch with registered `unsupported_capability`.
- “A dry run grants no continuing authority.” Preserve one pinned lease, fresh re-planning after elicitation, typed outcomes and one audit v2 record per entered lifecycle call.
- “An unknown mutation outcome is inspected, never automatically replayed.” No automatic retry, rollback, reopen or cleanup after a timeout/crash.
- “Returned diagnostics exclude credentials and do not echo rejected worker payloads.” Preserve strict decoding and one canonical document for text/structured content.
- “No operation-bearing PR is merge-ready without its own live evidence.” Fresh exact-fixture authorization and serialized Windows V21 execution are required at execution time.

## Review Focus

1. The typed owner's `.amc21` path is the public adoption/configured/status selector; `.als21` is an explicit-opening input and nullable provenance. Inventory directories prove neither a reverse identity join nor an ALS filename (Tasks 1–2, L01–L08).
2. Same-path re-verification must preserve binding revision and ownership; same-path close/reopen must invalidate old identity (Tasks 2–4, L07, L13, L18).
3. A clean worker-owned local session still cannot be silently discarded when another container opens or the last headless client detaches (Tasks 2, 4, L12, L15).
4. A working local session does not prove Project Server connectivity; unknown/authentication failure must not become connected, unlocked or current (Tasks 3–4, L02, L04, L16).
5. Reconnection/observation timestamps must not cause binding/cursor churn or compare different endpoints; post-open payload failure must preserve possible-mutation evidence (Tasks 1, 3–4, L13, L16–L18).

## Scope and lifecycle integration checkpoint

PR 4 extends existing tools, adding **no public tool and no inspection action**. `open_project(projectPath, forceRebind=false, dryRun=false)` accepts existing `.ap21` and `.als21` files; `.amc21` is not an opener. `bind_project` retains omitted/null/explicit `bind` and its six PR 3 inspections; local-session selection accepts the exact supported already-open owner's `.amc21` path, or an unambiguous no-path owner/Portal selection. `--project`, `--project=...` and `TIA_MCP_PROJECT_PATH` accept `.amc21` assertions for already-open local owners, not `.als21` assertions. Command-line precedence and duplicate-option rejection remain unchanged. A supplied `.als21` cannot select a cold-adopted owner; ordinary status and binding path assertions use the canonical `.amc21` path.

The existing optional positive `portalProcessId` argument becomes valid for the `bind` action; no argument or action is added. It selects one exact Portal before typed owner enumeration. With no path, require exactly one open context in that Portal; with a path, require exactly one matching typed owner. A different attached/bound PID follows explicit `forceRebind` conflict and preservation rules. Without an explicit PID, use supported deterministic advertised metadata or the sole candidate; otherwise return `target_ambiguous` before attaching. Never attach arbitrary Portals to search them. Inspection raw-key rules and verified foreign-PID refusal remain unchanged.

`get_project_status` gains only basic local-session/container status needed to verify/adopt the context. For local sessions its `metadata` remains null. This newly enabled status path is explicitly live-tested in this PR. Extended metadata, tree/PLC/network content reads, imports/writes, compile and local save stay undelivered for `.als21` until PR 5/6. `get_session_state` freshness and markings remain successor work; there is no PR 4 `IsUptoDate()` or marking query. PR 3 Portal/server inventory remains usable independently of an active container.

Current implementation seams to extend:

| Seam | Current behavior | PR 4 decision |
| --- | --- | --- |

| `ProjectSessionBinding` | Worker/PID/generation/path tuple | Retain tuple and ID/revision semantics; validate local context separately from observation timestamps |
| `MultiuserInventoryService` | Private endpoint observation history | Share typed observation history with the active context; inventory never adopts or opens |

Opening dispatch is `.ap21` → `Projects.Open(FileInfo)`, `.als21` → `LocalSessions.Open(FileInfo)`. Reusing an already-open exact destination invokes neither opener, but ALS reuse requires provenance tied to a continuously verified owner/generation or another supported exact join. A cold-adopted owner with unknown ALS provenance cannot be reused by path heuristics. If duplicate destination or source preservation cannot be established, refuse before dispatch; the implementation must qualify or explicitly narrow coexistence instead of relying on opener exceptions. Read-write still asks once for every actual lifecycle call, including proved exact-destination reuse; dry runs/full never ask. `forceRebind` permits selection only.

Opening a different destination from a worker-owned local-session source is conservatively blocked with `local_session_requires_terminal_operation`, even when clean. PR 9 supplies terminal operations. Opening from a UI-owned local-session source may preserve that session and open the exact destination only when supported coexistence is verified; never close/save/discard it. `bind_project` may switch to another already-open context when safe preservation is established, losing old worker ownership on detach/reattach. Last-client headless local-session detach is blocked whenever preservation cannot be proved, including clean state. Explicit selection failures before detach preserve a healthy binding; actual handle/worker loss invalidates it.
