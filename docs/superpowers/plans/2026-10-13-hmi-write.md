# `hmi_write` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A guarded `hmi_write` tool that creates, updates and deletes WinCC Unified tag tables, tags and
discrete/analog alarms in one call, with a dry run and a read-back verification.

**Architecture:** A new `IWriteDomain` on the existing `Safety/Pipeline` (`WriteExecution`), shaped like
`plc_write`: host catalog → planner (public `hmi_read` and cross-reference reads only) → guards → worker
mutation through nine `hmi_*` methods → verifier. The worker gains writers, an HMI locate cache and a
per-HMI snapshot drop; `hmi_read` rows gain four members.

**Tech Stack:** C# (host net10.0, worker net48, contracts netstandard2.0), Siemens Openness V21
(`Siemens.Engineering.HmiUnified`), xunit, ModelContextProtocol SDK.

**Spec:** `docs/superpowers/specs/2026-10-13-hmi-write-design.md` (read it with this plan; § numbers below
refer to it). Openness facts come from `docs/superpowers/acceptance/reports/2026-10-13-hmi-write-spike.md`.

## Global Constraints

- Tool counts 7/17/17; `hmi_write` registered only when `ProjectMutation` is allowed.
- Root `contractVersion:"1.0"` (`HmiWriteContractVersion.Current`); `hmi_read` stays `"1.1"`.
- 1–50 items, unique `operationId` ≤ 256 characters, caller order, stop at first failure, no rollback.
- Budgets 180,000 characters per response, 60,000 per value (`StructuredOperationBatchPayloadBudget`).
- Cross-reference cap: 200 queries per call. Planner list reads use `limit` 2000.
- `acquisitionCycle` ∈ `T100ms`, `T250ms`, `T500ms`, `T1s`, `T2s`, `T5s`, `T10s`; `triggerMode` ∈
  `OnRisingEdge`, `OnFallingEdge`; `condition` ∈ `LowerLimit`, `UpperLimit`, `Equal`, `NotEqual`,
  `LowerLimitOrEqual`, `UpperLimitOrEqual`; `priority` 0–255; `bitNumber` ≥ 0; `alarmKind` ∈ `discrete`, `analog`.
- Guard ids: `hmi_name_collision`, `hmi_state_unverifiable` (block); `hmi_deletes_table_contents`,
  `hmi_deletes_referenced_tag` (info).
- Typed setters only; never `SetAttributes`. Never dispose a `TiaPortalProcess`.
- Worker identity comparisons of live objects use `object.Equals`.
- No project name or project path in any repo file, test, commit or report.
- C# navigation through jCodemunch; builds `-m:1`; `dotnet` with `/p:` flags from PowerShell.
- One short one-line conventional commit per task, no body or trailers.
- Docs (README, AGENTS, `docs/`) change only in Task 12.

## Review Focus

1. `eventText` with `&`, `<`, `>` or `"` — expected: XML-escaped inside the wrapper and read back equal.
   Test: Task 3 `EventText_EscapesXmlSpecialCharacters`, Task 9 `EventText_EscapedTextVerifiesEqual`.
2. Delete a tag, then create `TAG` (case variant) in the same call — expected: no collision. Test: Task 7
   `DeleteThenCreateCaseVariant_DoesNotCollide`.
3. Omitted `hmiName` with zero or two Unified HMIs — expected `target_not_found` / `target_ambiguous` at
   plan time. Test: Task 8 `OmittedHmiName_ZeroOrTwoUnified_FailsAtPlan`.
4. An empty text array (`"comment": []`) — expected `validation_error`; an empty string text clears that
   culture. Test: Task 3 `EmptyTextArray_IsRejected_EmptyStringAllowed`.
5. A tag created and deleted in one call — expected: no cross-reference query; verified absent. Test:
   Task 8 `CreatedThenDeleted_NeedsNoCrossReferenceQuery`.
